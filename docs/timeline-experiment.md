# 进度条时间源实验

> 本实验已暂停并列为长期 TODO。当前版本第一字幕跟随 Netflix 原生轨道，以原生字幕匹配进行校准；以下内容保留为历史实验记录，不是当前用户操作要求。

## 当前实验：控制条隐藏时的内部时间源

本轮只增加日志，不改变字幕同步。点击“开始记录”后，每秒按有限字段名单读取播放器和控制条组件中的候选时间数值。不会调用发现的方法或 getter，不会触发 seek。通过弱引用继续观察之前找到的组件；对象可能消失或保留旧值，因此候选不能直接作为可靠时钟。

1. 在 `chrome://extensions` 或 `edge://extensions` 重新加载扩展，再刷新 Netflix 页面。
2. 工具选择两种字幕；Netflix 原生字幕选第三种语言。开始播放并点击“开始记录”，随后关闭扩展弹窗。
3. 广告前让控制条显示约 5 秒，再移开鼠标，让控制条隐藏。这样日志能先找到组件并记录基线。
4. 优先自然进入广告；也可拖动触发广告，但拖完立即移开鼠标。广告期间以及结束后 20–30 秒保持控制条隐藏，不拖动、不打开弹窗。
5. 然后移动鼠标，让控制条显示 5–10 秒，只显示，不点击或拖动。记录双语是否恢复。
6. 再移开鼠标，隐藏控制条继续播放 20 秒。最后打开扩展，停止并下载记录；下载前不要刷新。
7. 将 JSON 和“自然进入/拖动进入、广告后是否自动恢复、显示控制条后是否恢复”的观察一并提供。先做一轮即可。

日志应包含 `schemaVersion: 4`、`experiment: internal-timing-v1`，采样行约每秒附带 `internalTiming`：匿名 root 编号、player/control 来源、字段路径、数值或方法/访问器标记、是否仅通过旧弱引用找到（retained），以及扫描限制标记。retained 不代表值失效，fresh 也不代表值可靠；需要对照广告前后变化、原始时钟和进度条读数判断。数值单位尚未推断；扫描有字段、深度、对象数和时间预算限制，空列表不证明内部没有时间源。

仅记录允许的字段名与数值，不导出页面对象、组件文本、URL 或字幕内容。停止记录后不再发起探测；新录制、页面路径变化或采样中断超过 5 秒后重新发现。67 项自动测试、类型检查和 Chrome / Edge 构建通过；实际候选来源是否存在、能否用于首次校准仍待本轮验证。

## 已知问题与最新反馈

最新用户反馈：修复后反复显示/隐藏控制条不再造成字幕闪烁，已确认解决该现象。首次校准依赖可用进度条参考的问题仍未解决。

最新修订：针对 `02-05-37-193Z` 反馈，已将映射与 UI 验证样本分离。控制条重建、隐藏后重新出现、单个迟到读数不再清除有效偏移。多次连续读数形成稳定且明显不同的偏移后才撤销旧映射；真实广告/seek/媒体异常继续立即失效。65 项自动测试和两款构建通过，实机效果待验证。

本轮验收：广告后显示控制条直到双语恢复，再隐藏 20–30 秒，随后反复显示/隐藏控制条几次。整个过程中不应切回原生字幕；最后检查普通拖动和下一次广告仍可重新校准。若仍闪烁，下载日志。首次校准仍可能需要显示控制条，此问题尚未解决。

用户确认：修正候选控件查找范围后，显示进度条能够恢复广告后字幕；不移动鼠标显示控制条时，仍可能无法自动恢复。临时办法是广告结束后显示进度条数秒。校准后隐藏控件应继续使用有效映射，但真实持续效果仍待专项验收。

现有读取逻辑排除不可见控件。隐藏时 DOM 是否被移除、读数是否停止更新，尚未通过实测确定。下一步先观测隐藏控件生命周期与更新频率，再决定如何解除对显示控制条的依赖。63 项自动测试、类型检查及 Chrome / Edge 构建通过，不代表此已知问题已解决。

## 已接入的修复版：优先按此验收

进度条时间映射现已接入广告后恢复，原生字幕匹配与手动拖动恢复作为备用。62 项自动测试、类型检查及 Chrome / Edge 构建通过；真实 Netflix 自动恢复和时间精度仍待验收。下方“只读实验”记录是此前阶段说明。

1. 重新加载最新构建并刷新 Netflix，原生字幕选第三种语言，开启双语与日志记录。
2. 分别测试自然进入广告、拖动触发广告。广告期间应隐藏扩展双语。
3. 广告结束后不要拖动，移动鼠标显示控制条 5–10 秒，观察双语是否恢复、是否对齐。读数更新较慢时继续保持控制条可见，记录实际恢复时间。
4. 恢复后移开鼠标隐藏控制条，继续播放 20 秒；检查暂停/继续、普通 seek 和下一次广告。
5. 停止并下载日志。恢复失败也请先保存，随后可以拖动恢复；不要为采日志反复刷新。
6. 第三语言场景通过后，测试原生字幕关闭。若广告后控制条始终不显示，可能没有可用参考；此时应有等待提示，不能算完全自动恢复已实现。

日志 `syncMode: aligned-progress` 表示使用进度条映射；`syncProgress` 包含 `reason`、有效样本数、offset、spread（样本偏移极差，非实际同步误差）及 UI 秒值。无控件、单位不符、多个候选、读数过期或不一致时记录原因。首次读数不参与校准，至少五次后续有效更新、采集跨度至少一秒且偏移极差不超过 0.3 秒才建立映射；进度条单位须与视频总时长按毫秒吻合。稳定偏移不代表已证明绝对精度，需对照实际对白/字幕切换验收。

## 历史：只读实验

只增加诊断观测，不改字幕同步、播放器方法或 seek 行为。沿用“开始记录 / 停止记录 / 下载记录”。新版 JSON 的 schemaVersion 为 3，experiment 为 timeline-controls-v1。

1. 扩展管理页重新加载最新 `.output/edge-mv3` 或 `.output/chrome-mv3`，刷新 Netflix。
2. 工具选两种语言，Netflix 原生字幕选第三种语言，避免原生文本校准掩盖时间源变化。开启双语和记录。
3. 在正片、广告中、广告刚结束时各把鼠标移到播放器上，让控制条显示约 3–5 秒；不要点击或拖动。
4. 广告结束后等 10–15 秒，先观察进度条显示时间及原生字幕，再手动拖动一次。继续播放 10–20 秒，停止记录并下载。
5. 分别进行自然进入广告、拖动触发广告两轮；先下载第一轮再开始第二轮，避免覆盖。
6. 将两份日志和广告起止大致时间发来。若方便，截图记录广告结束但尚未拖动时的进度条显示时间。

新字段 timelineControls 最多包含 16 个候选控件：aria-valuenow/min/max、range 当前值、内联宽度及有限子元素宽度、aria-valuetext 中的时间格式片段。保留数值字符串和百分号，不假定单位为秒。候选也可能包含音量，index 仅代表当次 DOM 枚举顺序，不是稳定身份。

control-pointerdown/up、control-keydown、control-input/change 记录操作前后快照；interaction.fraction 是鼠标在控件宽度内的位置比例，不是播放器确认的 seek 目标。未拦截或调用播放器 seek。没有匹配到控件时列表为空，不能解释为时间为零；控制条隐藏时可能没有读数。

不收集页面文本、标题、URL 或任意键盘输入；键盘只记录方向键及 Home/End/PageUp/PageDown，且仅限候选控件。日志仍仅保存在页面内存，不上传，刷新前请先下载。56 项自动测试和类型检查通过；真实 Netflix 进度条字段与正片位置是否一致待实验验证。
