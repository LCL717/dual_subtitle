# Netflix 双轨字幕可行性

状态：待真实 Netflix 验证，未通过阶段 0。

当前只有 WXT 工程骨架和只读播放器检测。内容脚本按需检查播放页、video 元素与标准 TextTrack 数量，不提取字幕内容，不修改字幕模式。TextTrack 数量不能代表 Netflix 完整字幕菜单；弹窗不会将它作为可选语言列表。

## 待验证

- 当前影片网页字幕菜单的完整轨道列表与稳定标识。
- 两种不同语言字幕能否同时获取，不依赖持续切换原生字幕。
- 字幕格式、请求来源、最小权限和可能的页面上下文桥接。
- 两种语言独立按视频时间同步，处理 seek、全屏与切集。
- 两部影片、Chrome / Edge，以及含三种语言影片的组合切换。

尚无可记录的真实 Netflix 浏览器版本、轨道格式或字幕 CDN 域名。不要据此文件宣称自动双语显示已支持。

若无法实现，按 PLAN.md 报告阻碍并重新讨论范围，不自动改成字幕导入或机器翻译。

## 双轨资源检查与时间轴基础

在上下选择框中选择两种不同语言，再点击“检查所选字幕资源”。结果显示所选轨道是否存在下载元数据、内嵌 cue、格式标识及字段名称。仅有下载 ID 不代表已有可用下载地址；此步骤不下载字幕，不改变 Netflix 字幕。

本次增加独立时间轴查询模块，支持重叠 cue、结束边界、前后 seek 和两种语言断句不一致；尚未连接真实字幕或播放器渲染。

验证：13 项 Node 测试、TypeScript、Chrome / Edge 构建通过。真实资源结构待页面反馈，字幕内容获取及双语同步显示仍未完成。

## 真实轨道结构反馈与后续检查

用户反馈：Japanese 和 English 的公开轨道对象仅含 trackId、bcp47、displayName、trackType、rawTrackType、channels、isNoneTrack、isForcedNarrative、isImageBased、subType、variant，没有资源地址或 cue。

因此新增仅针对 netflix.player.MediaSession 的有界只读资源查找，以所选轨道 ID 精确匹配。检查最多 6000 个对象、14 层，分段让出主线程，并限制队列、字段和耗时。跳过访问器，不调用对象方法，不挂接 JSON.parse 或网络请求。不缓存原始播放器对象；地址不跨页面桥接或写入日志。

此路径来自对已有实现的研究方向，当前 Netflix 页面是否适用仍待验证。参考：https://greasyfork.org/en/scripts/575292-netflix-subtitle-downloader/code 。本项目独立实现了受限的属性描述符遍历，未复制其下载器代码，也未实现其字幕切换流程。

新增结果显示匹配轨道数量、检查对象数量和限制情况；未匹配不代表没有资源。重复标签依据 rawTrackType 标记 SDH，无法确定含义的同名轨道添加编号。

17 项自动测试、类型检查及 Chrome / Edge 构建通过。真实资源匹配、字幕下载、解析与双语叠加仍待验证或实现。
用户实测：所选 Japanese [SDH] 与 English [SDH] 已匹配 2/2 资源，格式均为 imsc1.1；下载与解析尚待验证。
